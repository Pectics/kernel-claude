# OpenClaw 基础设施架构

## 1. 基础设施层 (infra/)

OpenClaw 基础设施层提供了系统的底层支撑功能，包括网络、文件系统、进程管理、安全执行等核心能力。

### 1.1 网络和发现

| 模块 | 功能 |
|------|------|
| `bonjour.ts` | Bonjour 服务发现，支持 IPv4/IPv6 地址检测 |
| `tailnet.ts` | Tailnet 网络配置和地址管理 |
| `widearea-dns.ts` | 广域网 DNS 检测功能 |

### 1.2 文件系统安全

| 模块 | 功能 |
|------|------|
| `fs-safe.ts` | 安全的文件系统操作，防止路径遍历攻击 |
| `boundary-path.ts` | 管理文件访问边界，确保路径安全 |
| `tmp-openclaw-dir.ts` | 安全的临时目录管理 |

### 1.3 进程和执行

| 模块 | 功能 |
|------|------|
| `exec-approvals.ts` | 命令执行的安全审批机制 |
| `exec-safe-bin-policy.ts` | 管理二进制文件的执行策略 |
| `restart.ts` | 进程的优雅重启机制 |
| `restart-stale-pids.ts` | 处理过期的进程 ID 和重启逻辑 |

### 1.4 部署和更新

| 模块 | 功能 |
|------|------|
| `update-check.ts` | 检查系统更新 |
| `update-runner.ts` | 运行更新流程 |
| `install-package-dir.ts` | 管理包的安装过程 |

## 2. 配置管理 (config/)

### 2.1 配置加载

配置系统采用**分层加载机制**，支持多种配置源：

```
遗留配置检测 → 加载主配置 → 环境变量解析 → 应用默认值 → 验证配置 → 处理包含
```

| 模块 | 功能 |
|------|------|
| `io.ts` | 核心配置加载逻辑，支持 JSON5 格式 |
| `env-substitution.js` | 解析配置中的环境变量引用 |
| `merge-patch.ts` | 支持配置的增量合并 |
| `validation.ts` | 验证配置对象的合法性 |

### 2.2 配置结构

| 配置项 | 文件 | 描述 |
|-------|------|------|
| 代理配置 | `agent-dirs.ts` | 管理代理目录配置 |
| 能力配置 | `channel-capabilities.ts` | 定义通道能力 |
| 命令配置 | `commands.ts` | 配置命令行为 |
| 模型配置 | `config.ts` | 模型相关配置 |
| 路径配置 | `config-paths.ts` | 系统路径配置 |
| 会话配置 | `session-defaults.ts` | 会话默认值 |

### 2.3 配置管理特性

- **运行时刷新**: 支持配置的动态刷新
- **配置备份**: `backup-rotation.ts` 自动备份配置文件
- **配置迁移**: `legacy-migrate.ts` 从旧版本配置迁移
- **环境变量覆盖**: `runtime-overrides.ts` 运行时环境变量覆盖

## 3. 安全系统 (security/)

### 3.1 认证机制

### 3.2 授权检查

| 模块 | 功能 |
|------|------|
| `exec-approvals.ts` | 命令执行前的审批流程 |
| `exec-safe-bin-runtime-policy.ts` | 运行时的安全策略 |
| `exec-approvals-allowlist.ts` | 管理允许执行的命令 |

### 3.3 安全审计

| 模块 | 功能 |
|------|------|
| `audit-channel.ts` | 审查通道安全配置 |
| `audit-fs.ts` | 文件系统访问审计 |

- **Critical**: 关键问题检测

- **Info**: 信息提示
- 支持自定义检测规则

## 9. 最佳实践

### 9.1 配置管理

1. **环境隔离**: 使用不同的配置文件处理不同环境
2. **敏感信息**: 使用环境变量存储敏感信息，避免硬编码
3. **配置验证**: 启动时验证配置的完整性
4. **配置备份**: 定期备份配置文件

### 9.2 安全执行

1. **审批机制**: 任何外部命令都需要经过审批
2. **沙盒隔离**: 在沙盒环境中执行不信任的代码
3. **最小权限**: 遵循最小权限原则
4. **审计日志**: 记录所有执行操作

### 9.3 错误处理

1. **重试策略**: 对可恢复错误实现自动重试
2. **优雅降级**: 在关键服务不可用时提供基本功能
3. **错误分类**: 区分可恢复和不可恢复错误
4. **用户反馈**: 提供清晰的用户错误信息

### 9.4 性能优化

1. **懒加载**: 延迟加载重型资源
2. **连接池**: 复用网络连接
3. **缓存策略**: 合理使用缓存减少重复计算
4. **并发控制**: 限制并发操作数量

### 9.5 监控和诊断

1. **心跳检测**: 定期检查系统健康状态
2. **性能指标**: 收集关键性能指标
3. **日志结构**: 使用结构化日志便于分析
4. **错误跟踪**: 实现错误跟踪和报警

---

## 总结

OpenClaw 基础设施层采用模块化设计，各组件职责清晰，具有良好的可扩展性和可维护性。通过合理的安全策略和错误处理机制，确保了系统的稳定性和安全性。
